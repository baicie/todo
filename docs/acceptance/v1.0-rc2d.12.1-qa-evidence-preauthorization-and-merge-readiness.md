## B. P1：未授权目录创建已关闭

**修复前（`a623cf9`，真实行号）**

```text
547  let created = missing_components(&requested_root)?;
548  fs::create_dir_all(&requested_root)?;          // 先创建
554  verify_created_directories(&created)?;
555  let canonical_root = fs::canonicalize(&requested_root)?;
561  authorize_evidence_root(&canonical_root, roots, relative)?;   // 后授权
```

后果：把 evidence 路径配成 Stable 数据根（或它的子目录）、Dev 根、或任何未授权绝对路径时，
**目录树会先被创建出来，然后才拒绝**。拒绝的配置留下了文件系统副作用。

**修复后（`2485549`，真实行号）**

```text
608  split_evidence_path / validate_evidence_file_name          // 1. 结构与文件名
629  let intended = intended_evidence_root(&requested_root)?;    // 2. 不创建地解析
630  authorize_evidence_root(&intended.path, roots, relative)?;  // 2. 创建前授权
631  fs::create_dir_all(&requested_root)?;                       // 3. 仅在已授权范围内创建
640  verify_created_directories(&intended.created)?;             // 4. 创建后复查重解析属性
641  let canonical_root = fs::canonicalize(&requested_root)?;
647  if !same_path(&canonical_root, &intended.path) { fail closed }
655  authorize_evidence_root(&canonical_root, roots, relative)?; // 4. 再次授权
657+ reject_existing_directory + open(FILE_FLAG_OPEN_REPARSE_POINT) + verify_opened_evidence  // 5. 句柄级检查保持不变
```

**为什么预检是可靠的**：`intended_evidence_root` 取最近**已存在**祖先做 `fs::canonicalize`，
并要求每个待创建后缀组件必须匹配 `Component::Normal` —— `..`、根、前缀组件在创建前即被拒绝，
因此 intended 路径是「canonical 祖先 + 纯目录名」，只能落在预检判定过的范围内。

**第 6 项（残余风险，独立记录，未宣称解决）**：预检与 `create_dir_all` 之间，并发方仍可能把某个后缀组件
materialize 成重解析点。缓解是第 4 步的复查 + 严格规范化 + 再次授权（fail closed，不会穿透写入）；
彻底消除需要 openat 风格目录句柄或 `FILE_FLAG_BACKUP_SEMANTICS` + 每级目录句柄属性，属新依赖，本轮不做。

## H. PR #6 合并建议

**结论：代码可以合并；发布不可以。** 两者必须分开判断。

支持合并的证据：

1. 五个 D11 风险 + 本轮 P1 全部关闭，均有真实执行的回归测试（含两个按旧实现必然失败的新用例）。
2. 全部门禁在同一 HEAD 上通过；远端 CI 三个工作流 success，且 workflow 事务化后仍可加载。
3. D11/D12 的可靠性结论未回退：原生库 89→110、QA feature 91→133（+1 ignored），前端 102→115，E2E 18→20，release 契约 33→60。
4. 本轮安全修复的作用域被严格控制在一个文件内，且副作用契约有断言而非假设。

不建议「整体一次性合并」：PR #6 已达数十提交、跨 native/frontend/CI/文档。
建议按 D11 报告的 W1–W4 顺序分批合并（W1 身份 → W2 Activation/前端 → W3 QA 证据 → W4 发布流水线），
每批独立验收；**不需要**重写历史，可用 cherry-pick 到新分支，原分支作为整体证据保留。

合并前需维护者确认的唯一政策项：接受「发布流水线为 CONTRACT_ONLY、平台门禁 NOT_RUN」这一状态进入 main。
若该状态不可接受，则应先完成 G 节至少 Windows 安装/通知矩阵再合并。
