## 2. 设计决策与不变量

设计文档：[docs/design/native-rc2d.2-platform-acceptance.md](../design/native-rc2d.2-platform-acceptance.md)。

### 2.1 Notification rejection state machine

Native `NotificationActivationState` 增加 rejected queue：

```text
notification action
  -> validate account/registry/gate/task (fail-closed)
     -> invalid: append RejectedActivation { code, sanitized message }
        -> show window
        -> emit wake event only
     -> valid: append Activation (max 8)
        -> show window
        -> emit wake event only
```

Rejection queue:

- capacity 8; FIFO;
- overflow drops oldest (newest 8 retained);
- `native_take_notification_rejection` is pop-on-read; no ACK/retry state;
- event `native-notification-rejected` is only a wake-up; the message is never
  sent in the event payload;
- no token, task title, email or path in rejection records;
- queue is in-memory: process exit loses pending rejection notices (at-most-once
  UX); security remains fail-closed because no task is opened.

Invariants:

1. Invalid notification never opens a task, never switches account and never
   bypasses RuntimeGate/task existence.
2. Rejection delivery is bounded; >8 pending notices may drop the oldest.
3. One pop produces one UI notification; repeated wake events cannot duplicate
   the message.
4. Listener registration precedes startup drain; a pre-listener rejection is
   replayable while the process lives.
5. Abort/cleanup prevents any later `notify`/`openTask`.

### 2.2 Frontend delivery

- Both activation and rejection listeners are installed before the first drain.
- `requestDrain` serializes activation and rejection drains; max 8 per kind per
  cycle; `finally` requeues a wake that arrived at the loop boundary.
- Activation dispatch rechecks account and dedupes `activationId`.
- Rejection dispatch only sends `notify(message, 'danger')`; it never opens tasks.
- Native failure ends the current cycle; no busy retry.
- AbortSignal is checked at every await boundary; disposer idempotent.

## 3. 通知拒绝交付：失败、溢出、恢复

| 情形                      | 行为                                                |
| ------------------------- | --------------------------------------------------- |
| 拒绝早于 WebView listener | 队列保留；listener 安装后初始 drain 重放            |
| 连续 2–8 条拒绝           | FIFO，每条一次                                      |
| 超过 8 条                 | 丢弃最旧，保留最新 8 条；不阻塞安全路径             |
| 事件重复/风暴             | 仅唤醒；队列 pop 一次；不会重复 toast               |
| Native rejection 调用失败 | 当前 cycle 结束；下一次事件可再试；不忙循环         |
| WebView 初始化 abort      | listener 注销；队列结果留给下一次 bridge；不调用 UI |
| 进程退出/强杀             | 内存队列丢失；不打开任务；重启不恢复旧 rejection    |
| 账号切换后旧拒绝          | 可能显示通用拒绝提示；不打开旧账号任务              |
| 恶意/损坏 target          | Native 解析/校验拒绝；不进入 activation             |

`PREPARED` 重启后：

- recovery `target_committed=false`；
- journal phase 清空；
- active = source；
- source/target `DataSnapshot` fingerprint 不变（含 rows、outbox、cursor、
  device ID、schema、shadow、kv）。

`RESTART_REQUIRED` 重启后：

- recovery `target_committed=true`；
- finish 幂等；
- active = target；
- target/source `DataSnapshot` fingerprint 不变；
- `SwitchStatus.active=true`、phase 清空；
- target outbox 数量与重启前 snapshot 一致（不丢失/不重复）。

未能进程级验证的点保持 PARTIAL/NOT_RUN；没有为测试修改生产逻辑。凭据 Token
一致性未在该无凭据 accounts fixture 中验证，保持 NOT_RUN。

新增 `import_isolation` 测试使用 `read_snapshot()` 比较完整账户文件（包括
shadow/kv/outbox/cursor/device/schema），验证重复 ID 导入拒绝后 fingerprint 不变。
