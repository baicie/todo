## 2. Review P2 闭环

### P2 — PASS 无证据也能通过

评论：<https://github.com/baicie/todo/pull/5#discussion_r4373289512>

- `manual-platform.json` 升级 schema v2；每项包含 runId、headSha、app/installer hash、startedAt/finishedAt、observed、evidence、reason。
- `PASS` 强制要求：
  - 非空 `observed`；
  - 至少一项 evidence；
  - evidence 文件的 SHA-256 匹配；
  - 文件在 artifact root 内、非 symlink、不可路径穿越；
  - runId/HEAD/app/installer hash 与 manifest 一致；
  - 时间有效且 finishedAt ≥ startedAt。
- `NOT_RUN` 允许 null observed/evidence；`FAIL/PARTIAL` 要求 observed + reason。
- 新增 14 个负/正测试：合法 PASS、空 evidence、空 observed、缺失文件、错误 hash、错误 runId、错误 HEAD、路径穿越、junction/symlink、错误 app/installer hash、非法 status、重复/缺失/未知 ID、FAIL/PARTIAL 缺 reason。
- 测试使用受控临时文件并真实计算 SHA-256，不伪造固定证据。

### P2 — 场景清单与 manifest 一致

已在 RC2-D.4 用 `manual-scenarios.json` 单一来源修复；D.5 继续沿用，Harness 生成后执行 validator。

## 3. Windows E2E 设计

设计文档：[docs/design/native-rc2d.5-windows-e2e.md](../design/native-rc2d.5-windows-e2e.md)。

### 3.1 UIA Driver

`windows-toast-driver.ps1`：

- 检测交互式桌面、WpnService、WebView2；
- 使用 .NET UIAutomation；
- 只枚举 verified notification host 下的 `打开任务` Button；
- 通过 `InvokePattern` 触发，不使用盲坐标；
- `Click` 后仅返回 `PARTIAL`；必须由 E2E runner 观察到目标任务详情才允许 PASS；
- 截图仅截 Toast 窗口边界，不保存全桌面；
- 有超时、错误分类、清理和脱敏。

实际 Probe：desktopInteractive=true，WpnService=Running，WebView2=155.0.4283.62；未发现 Toast 按钮，`NOT_RUN`。

### 3.2 Toast E2E runner

`toast-e2e.mjs`：

- 启动 QA exe，连接 WebView CDP，验证 `qa_build_identity`；
- 通过 `todo_storage` 创建 QA-only task，通过 `schedule_reminder` 以 task id 触发带 action 的提醒；
- 调用 UIA driver；
- 若 driver 返回 PARTIAL，等待 WebView `aside.detail .detail__title` 等于任务标题；
- 只有真实 Toast 按钮被 invoke、任务详情实际打开且截图证据存在，才写 PASS。

本次实际执行 `running-app-activation`：

- QA task 创建成功；
- reminder 于 `02:00:56Z` 调度；
- driver 在 25 秒内未在 notification host 找到 `打开任务` 按钮；
- 结果 `NOT_RUN`，未写 PASS；未保留全桌面截图。

### 3.3 为什么不能 IPC 冒充

调用 `handle_action`、直接 emit event 或调用 `native_take_*` 只验证进程内业务逻辑，不证明 Windows Shell 展示了 Toast、按钮可被点击、进程被正确唤醒。此类结果只能是 `SIMULATED`，本轮没有用其升级任何平台 PASS。

### 3.4 冷启动/初始化边界

- 当前桌面 reminder queue 是进程内 timer；应用退出后不会再触发新的 Toast。历史 Toast/Action Center 的 AUMID 冷启动未在本轮获得真实点击证据，`cold-start-activation` 保持 NOT_RUN。
- M6/M7 的 “Native 已启动、队列可接收、WebView listener 未就绪” barrier 尚未实现；进程完全退出时内存队列已丢失，不能当作 pending FIFO 测试。
- 因此没有将“进程退出丢内存队列”误报为持久化缺陷。

## 5. Credential Manager

`credential-restart-e2e.mjs` 使用 QA 数据根和 QA credential service：

1. 启动 QA app，验证 QA identity；
2. 写入 `cloud-refresh:<qa-account>` 测试值（不是生产 token）；
3. 终止进程；
4. 重新启动；
5. 读取并确认值一致；
6. 删除并确认 get 返回 null。

结果：`status=PASS`、`restartedRead=true`，写入/读取/删除均成功，未记录 token 明文。
失败分支（Get/Set/Delete/旧 token 保留）由 mock/fault 单测覆盖；真实 Credential
Manager 失败注入和 A/B 凭据隔离 NOT_RUN。

## 9. 两轮独立审查

### 功能/架构

- 驱动只接受 notification host 内的 button，且 invoke 后仍为 PARTIAL；由 E2E runner 验证 WebView 任务详情。
- 证据校验拒绝无证据 PASS，路径穿越/symlink/hash 错误。
- 手动清单/生成 manifest/canonical IDs 一致。
- 真实 Toast 未观察到，未升级平台 PASS。

### 安全/对抗

- 修复了 driver 初始版本可能保存**全桌面截图**的隐私风险：现在只截 Toast 窗口，未发现 Toast 时不留截图。
- QA identity/data root/credential namespace 在 E2E/credential 脚本中强制校验。
- 没有新增生产 IPC；Toast fixture 使用现有产品 IPC，credential 测试只用 QA 键。
- 发现并修复 PASS 空证据、路径穿越/symlink、错误 hash/run/HEAD。
- 未发现 P0/P1；真实 Toast/cold start 是平台阻塞。
