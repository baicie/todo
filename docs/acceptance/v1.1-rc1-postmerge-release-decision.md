### 2.6 Shared Sync 安全回归（代码级）

| 测试文件                           | 项数 | 覆盖                                                        |
| ---------------------------------- | ---- | ----------------------------------------------------------- |
| `shared-account-isolation.test.ts` | 5    | A/B 双账号隔离、登出、切换、并发刷新、重启                  |
| `shared-legacy-cache.test.ts`      | 11   | 旧缓存读取隔离 + **同角色反例**：双方均不可读、不可认领     |
| `shared-sync.test.ts`              | 24   | Session fence、lost ACK、op_id 重复、409 rebase、撤销、删除 |
| `cloud-lifecycle.test.ts`          | 14   | 登出 / 切换 / token 刷新 / 离线                             |

关键断言（`shared-legacy-cache.test.ts`）：

- 同角色歧义时，B **不能**读取 A 的缓存、**不能** `bindAccount()`、**不能**重放 A 的 outbox；
- 拒绝路径**不写 binding、不改写任何行**，outbox 保持 `pending`；
- 原账号 A 也不能自动认领（无可靠身份标记），数据逐字节保留；
- 当角色重新唯一（peer 离开或新快照写入）后，A 仍可认领**同一份字节**。

这与任务要求的"无法归属的历史缓存不得自动认领、不得用新账号 Token 重放旧 Outbox、
不得删除用户唯一的离线数据副本"完全一致。
