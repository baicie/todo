## 1. 已确认并修复的问题

### P0-A：同步状态误报成功

**证据**

- `apps/app/src/sync/cloud.ts` 旧 `runSync()` 将所有非 `offline` 的 `SyncState` 映射为 `synced`，并用 `new Date().toISOString()` 兜底 `lastSyncedAt`。因此 `SyncEngine.syncNow()` 返回 `error`/`auth-required` 时，CloudPanel 仍可能显示已同步。
- `packages/sync/src/index.ts` 在服务器返回 `rejected` ACK 时只设置 `lastError`，随后仍按 pending 数量把状态置为 `synced`。

**修复**

- 新增 `apps/app/src/sync/cloud-status.ts`，由 `resolveCloudSyncOutcome()` 统一映射：
  - 只有 `status === synced`、`pendingCount === 0` 且没有 rejected 操作才返回 `synced`
  - `error`、`offline`、`auth-required`、`syncing` 分别保留
  - rejected 操作显示为 `error` 并带诊断信息
  - `lastSyncedAt` 只使用引擎返回的真实服务端时间；失败时保留旧成功时间，不伪造当前时间
- `apps/app/src/sync/cloud.ts:345` 使用该结果；`runInFlight` 串行化自动/手动/恢复同步，避免状态覆盖。
- 401 最多刷新一次；刷新失败或二次 401 进入 `auth-required`/`expired`，不会无限刷新。
- `packages/sync/src/index.ts:103` 修正 rejected ACK 状态；HTTP 5xx 不再被 `navigator.onLine` 误判为 offline。
- 失败时不清空 outbox、cursor、pending mutation；`handleSyncError` 只更新错误状态。

### P0-B：提醒查询截断和调度结果丢失

**证据**

- `apps/app/src/App.tsx` 的 `refreshReminders()` 使用 `listTasks({ limit: 1000 })`，超过 1000 个任务时有效提醒可能被遗漏，且每次普通任务变化都全量重调度。
- `apps/app/src/adapters/web-reminder.ts` 对超过 `setTimeout` 最大延迟的提醒直接返回，无法分阶段检查。
- `apps/native/src-tauri/src/commands.rs` 的 `reschedule_reminders` 清空全部队列、失败只 `eprintln!` 后返回 `Ok(())`；`ReminderAdapter::schedule` 返回 `Result<(), String>`，调度模式（inexact/outside-window/capacity）在边界丢失。

**修复**

- `packages/application/src/ports.ts:96` 增加 `ReminderScheduleStatus` / `ReminderScheduleResult`，覆盖 `scheduled`、`skipped-past`、`outside-window`、`permission-denied`、`capacity-exceeded`、`failed`。
- `apps/app/src/adapters/web-repository.ts:487` 与 `tauri-repository.ts:82` 增加专用 `listReminderCandidates()`；Web 使用 Dexie `remindAt` 索引，native 使用 `upcoming_reminders`，不存在 1000 条截断。
- `apps/app/src/reminders/reconcile.ts` 以 `remindAt + title + note` 指纹做增量 reconcile：未变化不重调度，删除/完成/撤销提醒取消；部分失败以 `issues` 返回，不报告整批成功。
- `apps/app/src/App.tsx:268` 接入 reconcile，并在冷启动、前台恢复、网络恢复、日期变化时执行；页面底部对未安排提醒给出可见告警。
- `apps/app/src/adapters/web-reminder.ts:39` 将长延迟拆成多个 `setTimeout` 阶段，页面存活期间持续检查。
- `apps/native/src-tauri/src/commands.rs:115` 返回 `ReminderReconcileReport`；`reminders.rs` 增加 `scheduled_ids()`，先取消过期/不存在任务，再调度当前任务，不再无条件清空全部通知；iOS capacity 错误映射为 `capacity-exceeded`。
- `crates/native-core/src/dispatch.rs:140` 增加 `list_reminder_candidates` 动作。

### P0-C：本地/离线回归发现的问题

- `packages/domain/src/tasks.ts:20` 的标签归一化在去掉 `#` 后没有再次 trim，输入 `# !` 会产生非幂等结果。已修复，并保留 property test。
- Dexie 数据库升到版本 4，新增 `remindAt` 索引；SQLite 新增部分索引 `idx_local_tasks_remind`，升级路径也创建该索引。
- 现有 `syncReplaceSnapshot`、`importData` 事务与 outbox 重放逻辑经回归验证，未发现需要重写的数据语义。
