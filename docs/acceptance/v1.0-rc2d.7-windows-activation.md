## 2. RC2-D.6 UIA 失败原因

D6 的 UIA 失败由**两个独立的 harness 缺陷**保证会发生：

1. `windows-toast-driver.ps1` 使用了
   `[string].Contains(string, StringComparison)`。Windows PowerShell 5.1 /
   .NET Framework 4.x 没有这个重载；调用抛出异常，而 `Test-WindowMarker`
   的 `catch {}` 吞掉了异常，导致 marker 永远不匹配。
2. `toast-e2e.mjs` 在 fireAt + 2500ms 后固定 sleep 3500ms，再同步启动 driver；
   Toast 横幅可能已经消失，driver 才开始搜索。

D7 已修复：

- 新增 `windows-toast-marker.ps1`，使用
  `IndexOf(string, StringComparison.Ordinal)`，并在 `powershell.exe` 5.1
  下执行 7 个 runtime tests（ASCII/中文/空/不同 marker）。
- Driver 不再吞掉 marker API 错误；stale UIA 元素异常只跳过该元素。
- Driver 在调度前启动，写 READY 文件；E2E 等 READY 后再调度。

最终实测：READY `10:21:53.816Z`，调度 `10:21:53.823Z`（早 7ms），仍无
on-screen button；说明 D6 的失败**并非只由 harness 缺陷造成**，Windows 当前
也没有把 Toast 横幅暴露给 UIA。两个 harness 缺陷是真实且已修复的，但不能
覆盖平台呈现问题。

## 4. Phase B — 原生激活

### 现状

- `tauri-plugin-notification 2.7.0` + `notify-rust 4.18`。
- Windows 仅安装后正常；QA NSIS 有 Start Menu 快捷方式/AUMID。
- 插件文档：点击只在 Toast 仍显示在屏幕时报告。
- 当前单实例插件只负责已有进程的第二实例转发；不提供将 Action Center Toast
  映射到冷启动进程的 COM activation。

### ADR 结论

三个场景：

1. **运行中横幅点击**：理论可用；本轮因平台未暴露 on-screen button，NOT_RUN。
2. **通知中心点击**：当前插件构造不支持离开屏幕后的 action 回调；NOT_RUN。
3. **进程退出后从通知中心启动并打开任务**：当前架构无原生激活入口；
   NOT_RUN。

备选方案（未实施、无 PASS）：

- A. Windows App SDK `AppNotificationManager` + COM activation + AUMID/快捷方式
  registration；需要 Windows 专属适配层、单实例参数、账号隔离和安装升级设计。
- B. 自定义 Windows COM Toast activator，替换/包住 notify-rust；风险/成本最高。
- C. 明确收缩 Windows v1 能力：只支持运行中横幅，通知中心/冷启动不承诺。

本轮不替换生产通知 backend；没有用 synthetic callback 伪造冷启动。详细限制见
设计/RFC 建议。
