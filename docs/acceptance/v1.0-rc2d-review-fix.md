## B. Review 问题闭环

### B1. P1 — Replace import 可产生重复 create outbox

**原始问题**
Replace 模式将每行 `exists=false`，但 bundle 未拒绝重复 entity ID。重复 ID 在本地 UPSERT 成最后一条，outbox 却可能包含多个 `create`；服务端第二个 create 返回 `ENTITY_ALREADY_EXISTS`，本地/云端可能分歧。

**根因**
`import_data` 的 `replacing` 分支为每条记录跳过 `SELECT EXISTS`；同时导入前只校验格式、标题/清单名，没有按实体类型校验 ID 唯一性。

**修改**

- `crates/native-core/src/store.rs`
  - 新增 `validate_unique_import_ids`：lists、tasks、steps、day_plans 分别校验，不要求跨实体类型全局唯一。
  - 校验在取得 SQLite 锁和开启写事务**之前**执行；错误为明确的 `Validation` 文本并包含实体类型和重复 ID。
  - 恢复四类实体的逐行 `SELECT EXISTS`，不再根据 Replace 直接推断 create；Replace 的 DELETE/事务/outbox 协议不变。
- 保留 Replace 的事务原子性；重复校验失败时数据库和 outbox 均未触碰。

**新增回归测试**（`crates/native-core/tests/repository.rs`）

- `replace_import_rejects_duplicate_list_ids_before_writing`
- `replace_import_rejects_duplicate_task_ids_before_writing`
- `replace_import_rejects_duplicate_step_ids_before_writing`
- `replace_import_rejects_duplicate_day_plan_ids_before_writing`
- 每个测试同时断言：list/task/step/day-plan 数据不变、outbox JSON 完全不变。
- `replace_import_allows_same_id_across_entity_types`：不同实体类型可共享 ID。
- `merge_import_preserves_unique_rows`：合法 Merge 契约保持。
- 既有 `export_import_roundtrip_and_clear_all_keep_device` 继续覆盖合法 Replace。

**验证**

```text
cargo test -p todo-native-core --test repository import
# 7 passed
cargo test --workspace
# PASS
cargo clippy -p todo-native-core -p todo-native-accounts --all-targets -- -D warnings
# PASS
```

**遗留风险**
唯一性校验使用一个实体类型内的 HashSet，内存 O(n)，不改变事务边界；未新增跨实体全局唯一限制。服务端对重复 create 的兼容路径不需要改动。

### B2. P2 — 默认 QA 命令找不到实际 EXE

**原始问题**
`run-windows.ps1` 默认候选为 `Shishi QA RC2D.exe`，实际 Cargo/NSIS 产物是 `todo-native.exe`；`-Build -Install` 会安装成功但随后报 `QA executable not found`。

**根因**
候选列表按 Tauri `productName` 猜测可执行文件名，忽略了 Cargo package name `todo-native`；同时构建步骤用 PowerShell 5.1 的 `ErrorActionPreference=Stop` 处理 native stderr，pnpm 正常进度输出会被当作异常终止构建。

**修改**

- `scripts/qa/native/run-windows.ps1`
  - 默认候选改为 `target/release/todo-native.exe`、`%LOCALAPPDATA%\Shishi QA RC2D\todo-native.exe`、`%LOCALAPPDATA%\Programs\Shishi QA RC2D\todo-native.exe`。
  - `-Install` 时优先已安装路径；非 `-Install` 时优先构建产物。
  - 新增 `-DiscoverOnly`：只做路径和 ProductName 校验，不启动应用；CI 中可重复执行。
  - 保留非文件名的 QA 校验：ProductName 必须为 `Shishi QA RC2D`；运行时 harness 继续调用 `qa_build_identity` 校验 `app.shishi.todo.qa` 和 QA credential service。
  - 构建阶段局部将 `$ErrorActionPreference` 设为 `Continue`，仅以 `$LASTEXITCODE` 判断 pnpm/Tauri 结果，避免正常 stderr 被当作失败。
- `.github/workflows/native-qa.yml` 在 QA bundle 构建后执行 `run-windows.ps1 -DiscoverOnly`。

**新增/可重复验证**

```powershell
./scripts/qa/native/run-windows.ps1 -DiscoverOnly
# Discovered QA exe: <repo>\apps\native\src-tauri\target\release\todo-native.exe
# ProductName: Shishi QA RC2D

./scripts/qa/native/run-windows.ps1 -Install -DiscoverOnly
# Discovered QA exe: <user>\AppData\Local\Shishi QA RC2D\todo-native.exe
# ProductName: Shishi QA RC2D
```

**Windows 实际验收**

- 执行文档流程：`./scripts/qa/native/run-windows.ps1 -Build -Install -AllowPartial`
- Build：PASS（NSIS 3.45 MiB）
- Install：exit 0
- 默认发现：安装目录 `todo-native.exe`（未传 `-AppExe`）
- Native identity：`qa_build_identity` PASS（`app.shishi.todo.qa`，QA credential service）
- Production data root：运行前后均不存在
- Run：`rc2d-20261025T075344Z`，8 PASS / 0 FAIL / 4 NOT_RUN，manifest PARTIAL
- App/installer SHA-256 见证据 README

**遗留风险**
`-AllowPartial` 是研究性证据运行所必需：真实 Toast/双账号测试为 NOT_RUN，gate 模式仍会返回非零。不得把 `-DiscoverOnly` 或 ProductName 检查当成真实平台验收。

### B3. P2 — 无实际作用的 notification ACK

**原始问题**
`native_take_notification_activation` 使用 `take()` 弹出激活，前端随后调用 `native_ack_notification_activation` 永远返回 false；接口让维护者误以为存在确认重试语义。

**根因**
交付契约实际是 pop-on-read，但保留了 ack 命令、队列 `acknowledge` 方法和前端调用。

**决策**
保持简单、可测试的**一次性消费**契约：`take` 即交付；不引入 peek/ack 状态机、不加重试状态。

**修改**

- 删除 `native_ack_notification_activation` 命令、`acknowledge` 方法和 lib invoke 注册。
- 删除前端两处 `native_ack_notification_activation` 调用。
- 保留 Native delivery 时的 account/store/gate/task 重新校验、pending 队列上限和重复读取返回 None。
- 更新 design/report：明确 pop-on-read；不再声称有 ACK 重试。

**新增测试**

- `activation_is_consumed_once`：首次 take 得到激活，第二次 take 返回 None。
- `activation_queue_preserves_click_order_and_drops_oldest`：队列顺序与上限。
- 既有 malformed target/legacy 测试保留。

**遗留风险**
一次性消费意味着 renderer 在 take 后崩溃会丢失该 activation；这是当前产品契约的明确取舍，不是静默 ACK。真实 Toast 点击仍 NOT_RUN。
