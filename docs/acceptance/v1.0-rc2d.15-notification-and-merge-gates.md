## F. QA Binary Provenance

- `build.rs` 解析 commit（`QA_BUILD_COMMIT` → `QA_GIT_COMMIT` → `git rev-parse HEAD`，非法则 `unknown`），
  通过 `cargo:rustc-env` 编译期内嵌。
- `commands.rs` 内嵌单一字面量 `QA_BUILD_COMMIT:<sha>`，并经既有 `qa_build_identity` 的 `buildCommit` 字段暴露
  （**未新增 WebView 命令**）；可执行文件字节中的值与 IPC 报告值取自同一字面量，无法漂移。
- `harness-target.mjs` 新增 `-ExpectedCommit` / `-AllowCommitMismatch`、`COMMIT_MISMATCH`、`EXPECTED_COMMIT_INVALID`，
  provenance 记录：报告 commit、来源（embedded / sidecar / unknown）、信任标签、期望 commit、是否匹配、是否显式允许不一致。
- **信任边界**：sidecar 文件（`<exe>.qa-build.json`）可被编辑，代码与运行输出均标注其为**较弱证据**；
  编译期内嵌为主机制。策略版本升至 `harness-target/v2`，旧运行证据可区分。
- 实测：`-ExpectedCommit <HEAD>` → `MATCH`；错误 commit → exit 1 `COMMIT_MISMATCH`（打印双方 SHA）；`-AllowCommitMismatch` → `MISMATCH_ALLOWED`。
- **NOT_RUN**：对运行中应用经 IPC 读取 `qa_build_identity`（harness.mjs 由另一工作包持有）；
  链路是结构性的（测试 8 断言三处共享同一 marker），未经 GUI 观测。
