## G. Native Activation Gateway

`notification_activation.rs` 新增：

- `listener_ready(sessionId)`：建立 WebView listener session。
- `take_for_listener(sessionId)`：只有 ready session 且没有 in-flight 时才交付；交付前重新验证账号、RuntimeGate、任务存在。
- `acknowledge(sessionId, activationId, outcome)`：`opened/rejected/expired/duplicate`；session-bound；未知 ACK 返回 false。
- In-flight 激活不会在 ACK 前被丢弃。
- Listener reload：旧 session 的 in-flight 最多 requeue 一次；第二次 reload 产生 `ACTIVATION_EXPIRED` 拒绝，不静默丢失。
- 已完成目标/激活 ID 有界去重（32），重复点击不重复打开。
- 队列上限 8、drain 每次最多 8；账号/任务校验保持原有 Native 权威边界。

Tauri 命令：

```text
native_notification_listener_ready(sessionId)
native_take_notification_activation(sessionId)
native_ack_notification_activation(sessionId, activationId, outcome)
native_take_notification_rejection()
```

用 CDP 对已安装 build 验证：

```text
ready -> true
take  -> null
ack unknown -> false
```

Rust tests：17 notification/activation tests + 全部 native lib 62 tests（serial）PASS。

## H. Listener Ready / ACK Barrier

前端 `notification-activation.ts`：

- 启动时生成 sessionId，先调用 `native_notification_listener_ready`，失败则 bridge 初始化失败。
- `native_take_notification_activation` 携带 sessionId。
- `openTask` 成功后 ACK `opened`；异常 ACK `rejected`；账号不匹配 ACK `rejected` 并提示。
- ACK 失败保留 Native in-flight，下一次 listener session 走一次 requeue，不重复打开。
- 事件仍只作为 wake-up；真正数据来自 Native 有界队列。

前端测试：8 个测试文件、85 tests PASS（其中新增 ready-before-drain、opened ACK、rejected ACK）。
