## 3. 设计与状态机不变量

设计文档：[docs/design/native-rc2d.3-reliability.md](../design/native-rc2d.3-reliability.md)。

### 3.1 内部错误 vs 用户可见

- 内部：`AccountError`、`StoreError` 等只用于 Native 分支判断；不进入用户可见队列。
- 用户可见：`RejectedActivation { code, message }` 只由 `RejectionCode` 构造。
- message 固定、简短、无路径/邮箱/Token/任务标题/SQL。
- 诊断只保留稳定 code 分类；不把原始 `Display` 写日志。

| Code                                                    | 固定消息                               |
| ------------------------------------------------------- | -------------------------------------- |
| `APP_NOT_READY`                                         | 应用尚未完成初始化，请稍后重试         |
| `DATA_DIR_UNAVAILABLE`                                  | 暂时无法读取本地账号数据               |
| `ACCOUNT_REGISTRY_MISSING` / `ACCOUNT_REGISTRY_INVALID` | 本地账号状态不可用，请检查账号恢复状态 |
| `ACCOUNT_SWITCH_REQUIRED`                               | 该提醒属于另一个账号，请先切换账号     |
| `ACCOUNT_SWITCH_IN_PROGRESS`                            | 账号切换进行中，请稍后重试             |
| `TASK_NOT_FOUND`                                        | 提醒对应的任务已删除或不可见           |
| `TASK_READ_FAILED`                                      | 暂时无法读取提醒对应的任务             |

### 3.2 Queue contract

| 阶段                 | 契约                                                      |
| -------------------- | --------------------------------------------------------- |
| Native 验证目标      | fail-closed；失败只产生 rejection，不产生 activation      |
| activation queue     | FIFO，容量 8，溢出丢最旧                                  |
| rejection queue      | FIFO，容量 8，溢出丢最旧                                  |
| pop-on-read          | 一次读取消费一条；空返回 null；无 ACK、非 exactly-once    |
| 进程退出             | 内存队列丢失；不打开任务；at-most-once UX                 |
| 前端 activation take | 再校验 active account，按 activationId 去重，最多打开一次 |
| 前端 rejection take  | 只 notify；不打开任务                                     |
| 事件                 | 仅 wake-up；消息只从队列读取，避免重复 toast              |
| cleanup              | abort/dispose；队列留在 Native，后续 bridge 可消费        |
| Native 失败          | 结束当前 cycle；后续 wake 可重试；不忙循环                |
| wake 合并            | 串行 cycle；每轮每类最多 8；结束边界 wake 重新排队        |
| 调度                 | activation/rejection 不交叉消费；各自保持 FIFO            |

## 5. 通知队列边界测试

前端 `notification-activation.test.ts` 现有 **24 tests**，新增覆盖：

- 第 8/9 条 rejection 边界：首轮消费 8 条，wake 后再消费第 9 条；
- activation 与 rejection 在同一轮 drain 中独立消费，不互相消耗；
- rejection drain 失败不阻止 activation 投递；
- rejection Native 失败后新 wake 可重试；
- cleanup 与 rejection invoke 竞争时不显示消息；
- 重复 wake 不产生重复 toast，并限制 invoke 次数，防止忙循环；
- 既有 abort/cleanup、listener 注册、初始 drain、FIFO、去重、账号不匹配测试保留。

全部 **24 passed**；全前端 **82 tests / 8 files**。

## 6. 真实进程崩溃恢复矩阵

### 6.1 方法

- `crash_faults.rs`（`fault-injection` feature）子进程安装 QA/测试专用 `TerminatingInjector`，在指定 `FaultPoint` 执行 `std::process::exit(99)`。
- 父进程断言子进程**实际退出码 99**，再在父进程执行真实 `recover_pending_switch` / `finish_pending_switch`。
- 不使用 sleep 竞态；Ready 不参与，故障点即退出点。
- `sigkill.rs` 继续保留真实 SIGKILL + 重启测试。
- 比较 `read_snapshot()` 完整 fingerprint（rows、counts、outbox、shadow、kv、cursor、device、schema、bound account/API）。

### 6.2 结果

| 边界                                                                                   | 方法                                          | 结果                                                               |
| -------------------------------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------ |
| `SwitchPreparedPersisted`                                                              | child prepare → exit 99 → restart recovery    | **PASS**：journal 丢弃，source active，source/target snapshot 不变 |
| `SwitchRestartRequiredPersisted`                                                       | child request → exit 99 → restart             | **PASS**：target committed，finish 幂等，target outbox 不丢        |
| `SwitchVerifyingTargetPersisted`                                                       | child recover → exit 99 → retry               | **PASS**：journal VERIFYING；retry 提交                            |
| `RegistryActiveBeforeUpdate`                                                           | child recover → exit 99 → retry               | **PASS**：registry 仍 source；retry 提交                           |
| `RegistryActiveAfterUpdate`                                                            | child recover → exit 99 → retry               | **PASS**：registry target；retry/idempotent                        |
| `SwitchJournalBeforeCleanup`                                                           | child recover+finish → exit 99 → retry finish | **PASS**：journal 保留；retry 清理                                 |
| `PREPARED`（OS SIGKILL）                                                               | 既有 `sigkill` child.kill                     | **PASS**                                                           |
| `RESTART_REQUIRED`（OS SIGKILL）                                                       | 既有 `sigkill` child.kill                     | **PASS**                                                           |
| Target DB corrupt                                                                      | `corrupt_target_rolls_back_to_source...`      | **PASS**：fail-closed，source restored                             |
| journal FAILED repair                                                                  | `failed_journal_repairs...`                   | **PASS**                                                           |
| journal cleanup retry                                                                  | fault tests                                   | **PASS**                                                           |
| 外部 SQLite 写锁                                                                       | `repository` 真实 `BEGIN IMMEDIATE`           | **PASS**：busy/locked，无部分状态                                  |
| 准备前、源 DB close、目标 DB open、身份校验、FAILED 写入前后、rollback、恢复中再次中断 | 无确定性进程 hook                             | PARTIAL / NOT_RUN                                                  |
| 凭据 Token 崩溃一致性                                                                  | 无真实凭据 fixture                            | NOT_RUN                                                            |

真实进程退出通过不等于断电级持久性通过；报告中按此区分。
