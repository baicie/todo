## D. REGDB_E_CLASSNOTREG Root Cause

证据：

```text
MddBootstrapInitialize2 = 0
AppNotificationManager.IsSupported = True
AppNotificationManager.Default = OK
AppNotificationManager.Register = HRESULT 0x80040154
```

`0x80040154` = `REGDB_E_CLASSNOTREG`（COM class not registered）。

归类：**UNKNOWN_WITH_DIAGNOSTICS**，候选根因
**COM_REGISTRATION_MISSING**，不是单纯部署模式冲突。

已排除/未排除：

- 已排除：Bootstrap 失败、Self-contained DLL 缺失、AppNotification 不受支持、
  进程 AUMID 未设置、架构错误。
- 未证明：具体哪个 CLSID/COM activation 返回 CLASSNOTREG；managed exception
  不暴露 CLSID，当前环境没有可用的 native debugger/ETW 快照。
- 现有官方 issue 记录 self-contained Register 的资源 DLL/激活问题
  （microsoft/WindowsAppSDK#6071、#6774）；本机表现 HRESULT 不同，不能直接
  套用结论。

没有执行 regsvr32、HKCR 猜测写入、系统 Runtime 重装或通知策略修改。

## G. WebView Timeout Cancellation

前端 `openTask` 契约改为：

```text
openTask(taskId, AbortSignal) -> Promise<boolean>
```

实现：

- 每个 activation 独立 AbortController；
- 5s timeout 主动 `controller.abort()`；
- dispose / listener abort 立即 abort 当前 openTask；
- `Promise.race` 只用于结果等待，**迟到 Promise 的提交必须检查 signal**；
- App 在 `repository.getTask()` 后再次检查 signal/disposed/account；
- 详情标题实际渲染（最多 10×50ms 轮询）后才返回 true；
- 迟到结果不能 `setSelectedTask` 或 ACK opened。

测试：

- timeout 后 abort 被调用；
- 迟到 resolve 不产生 opened ACK；
- abort while loading；
- task missing / repository throw；
- ready-before-drain；
- opened/rejected ACK 参数。

Frontend tests：**88 PASS**。

## I. Notification Identity / Dedup Semantics

新增 `NotificationTargetV1.notification_id: Option<String>`：

- 新提醒 worker 为每次通知生成实例 ID：
  `Utc.now_millis + sequence`；
- action arguments 编码为
  `shishi.task.v1:<account>:<task>:<notification-instance>`；
- 旧 token 无实例 ID 时保持 target-key 去重（兼容旧通知）；
- 同任务不同通知实例不被 taskId 永久抑制；
- 同一实例重复点击由 target 去重 TTL/容量抑制；
- activationId 仅用于 ACK 幂等，不承担 target 去重。

限制：通知实例 ID 在进程重启后不使用持久化计数；使用时间戳+进程序列，跨进程
唯一性依赖毫秒级时间与队列顺序；不会作为授权依据。
