## 2. Review finding 闭环

### P2 — 四个 crash 测试缺少完整快照

评论：<https://github.com/baicie/todo/pull/5#discussion_r4371285705>

修复：

- `process_exit_at_verifying_target_retry_commits_target`
- `process_exit_before_registry_update_retry_commits_target`
- `process_exit_after_registry_update_retry_is_idempotent`
- `process_exit_before_journal_cleanup_retry_finishes`

四个测试均在 fault 前记录 source/target `DataSnapshot`，恢复、finish、第二次恢复后比较完整快照；同时断言：

- 子进程真实退出码 99；
- fault 时 journal phase；
- fault 时 active account（source 或 target）；
- 恢复后 active account；
- journal 清理/保留；
- 第二次 recovery 不修改已提交状态。

`DataSnapshot` 的 fingerprint 输入覆盖 `integrity`、counts、table digests、device ID、cursor、client seq、bound account/API、outbox rows、shadow rows、schema versions；测试比较完整 `DataSnapshot`（不是只比 ID/标题/数量）。

修复 commit：`c4adfd1`。

## 3. 崩溃矩阵与快照结果

`crash_faults.rs` 共 **9 个真实子进程终止测试**（child 为 `#[ignore]`，父测试显式
spawn 并以 `std::process::exit(99)` 断言，不把 ignored child 计作独立场景）：

| #   | 测试                                                                       | 故障点/操作                                      | 结果     |
| --- | -------------------------------------------------------------------------- | ------------------------------------------------ | -------- |
| 1   | `process_exit_after_prepared_persisted_discards_journal`                   | `SwitchPreparedPersisted` / prepare              | **PASS** |
| 2   | `process_exit_after_restart_required_commits_target`                       | `SwitchRestartRequiredPersisted` / request       | **PASS** |
| 3   | `process_exit_at_verifying_target_retry_commits_target`                    | `SwitchVerifyingTargetPersisted` / recover       | **PASS** |
| 4   | `process_exit_before_registry_update_retry_commits_target`                 | `RegistryActiveBeforeUpdate` / recover           | **PASS** |
| 5   | `process_exit_after_registry_update_retry_is_idempotent`                   | `RegistryActiveAfterUpdate` / recover            | **PASS** |
| 6   | `process_exit_before_journal_cleanup_retry_finishes`                       | `SwitchJournalBeforeCleanup` / recover+finish    | **PASS** |
| 7   | `process_exit_after_failed_journal_restores_source_and_keeps_target_bytes` | `SwitchFailedPersisted` / recover invalid target | **PASS** |
| 8   | `process_exit_after_rollback_failed_journal_restores_source`               | `SwitchFailedPersisted` / rollback               | **PASS** |
| 9   | `recovery_interrupted_twice_still_commits_once`                            | registry before + after，同一恢复流程两次中断    | **PASS** |

关键断言：

- 1：journal PREPARED 后丢弃；source active；source/target snapshot 不变。
- 2：journal RESTART_REQUIRED；恢复 target committed；finish 幂等。
- 3：fault journal VERIFYING、source active；retry 提交；第二次 recovery 不再修改。
- 4：fault journal VERIFYING、registry source；retry 提交。
- 5：fault journal VERIFYING、registry target；retry 幂等。
- 6：fault journal VERIFYING、registry target；retry finish 清理。
- 7：FAILED journal 先持久化；源恢复；损坏 target 字节不变；重复 recovery 仍 fail-closed。
- 8：rollback FAILED journal 先持久化；source active；完整 source/target snapshot 不变。
- 9：两次终止后第三次 recovery 只提交一次；完整 snapshot 不变。

既有证据继续成立：

- `sigkill.rs` 真实 OS SIGKILL + 重启：PREPARED / RESTART_REQUIRED **PASS**。
- `corrupt_target_rolls_back_to_source_without_creating_empty_target` **PASS**。
- `failed_journal_repairs_a_target_pointer_left_by_an_interrupted_rollback` **PASS**。
- 外部 SQLite `BEGIN IMMEDIATE` 写锁测试 **PASS**。
- `import_isolation` 完整 snapshot **PASS**。
