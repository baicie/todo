## 1. 修正后的归属判定

旧设计“旧库一律迁入 anonymous default”已废弃。迁移只读检查：

| 判定       | 条件                                                                                 | 行为                                                       |
| ---------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| 匿名       | 无 `bound_account`，且 `sync_enabled != true`                                        | 迁入 `accounts/default`                                    |
| 已绑定     | `bound_account` 是合法规范化邮箱；`device_id` 存在；outbox 中所有 device_id 与之一致 | 迁入稳定 UUID 云账号目录，active 指向该账号                |
| 归属不明   | 绑定邮箱非法/缺失但 sync 已启用/绑定存在但 device 缺失/outbox device 不一致          | 保留源库，创建备份，写 `REQUIRES_REVIEW`，不创建账号或空库 |
| 元数据损坏 | registry/state JSON 损坏、active 不存在                                              | 启动报错，禁止创建空库掩盖数据                             |

未知归属不会自动绑定给任何云账号；RC2-A 也没有“确认归属”UI，因此安全策略是阻断启动并保留可恢复路径。

## 2. 目录与注册表

```text
app_data_dir/
  accounts.json
  migration-state.json
  accounts/
    default/shishi.sqlite3
    <opaque-uuid-v7>/shishi.sqlite3
  migration-backups/
    <timestamp>-shishi.sqlite3
    quarantine-target-<uuid>.sqlite3
  shishi.sqlite3                 # 旧库，迁移后保留
```

- `accounts.json` 只保存非敏感元数据：`id/kind/email/apiUrl/createdAt/schemaVersion/lastOpenedAt`。
- 账号 ID 只能是 `default` 或规范 UUID v7；邮箱不进入路径。
- 路径由 Rust 派生，WebView 不能提交数据库路径。
- 账号目录做 symlink/目录归属/canonicalize 校验；数据库文件本身拒绝 symlink。
- JSON 使用同目录临时文件 + fsync + 原子替换；Windows 使用 `ReplaceFileW`，失败时执行保守两步回退并保留旧文件。
- registry 缺失、损坏、active 缺失都不会自动初始化空库，除非确认是全新安装。

## 3. 迁移状态机

```text
NOT_STARTED
  -> BACKUP_CREATED
  -> COPY_VERIFIED
  -> REGISTRY_COMMITTED
  -> COMPLETE

REQUIRES_REVIEW   # 归属不明
FAILED            # 可重试；源库、备份保留
```

- SQLite Backup API 生成一致性备份；WAL 中未 checkpoint 的数据也会进入备份（真实测试覆盖）。
- 目标库通过 `PRAGMA integrity_check`，并进行整库快照比较：
  - 任务/列表/步骤/day plan 数量；
  - outbox 全字段与 clientSeq/opId；
  - server_shadow 全字段；
  - device_id、sync_cursor、client_seq、bound_account；
  - schema_migrations。
- 迁移只复制 SQLite 数据，不生成新 outbox、不触发同步、不改 device identity。
- 目标先写临时文件，验证后 rename；损坏目标会先隔离到 backups，不删除唯一数据。
- 完成标记在目标与 registry 都持久化且重新验证后才写。
- 重复启动：COMPLETE + target 存在直接打开；中断状态从备份恢复；不会通过“文件存在”判断成功。

## 4. 凭据与 WebView 边界

- Refresh token 键：`cloud-refresh:default`（legacy）与 `cloud-refresh:<account-id>`。
- `secure_tokens::migrate_legacy_refresh_token` 只在数据库归属验证为 cloud 且迁移发生时调用；匿名/归属不明不迁移。
- 前端配置键：`shishi.cloud.config` / `shishi.cloud.config.<account-id>`。
- 启动顺序：native migration/registry → 打开唯一 SQLite → `native_account_context` → 前端写入 account profile/active id → 动态加载 App/cloud.ts。
- 旧 cloud config 仅当其 email 与已验证绑定一致时才复制到账号键；不一致不复制并保持 disconnected。
- RC2-A 不提供账号切换；`AppState` 仍只有一个 `Arc<TodoStore>`，没有热切换写入路径。

## 5. 数据丢失风险分析

| 风险                      | 处理                                                                         |
| ------------------------- | ---------------------------------------------------------------------------- |
| 旧库被直接移动/删除       | 不移动、不删除；只读 + Backup API                                            |
| WAL 未 checkpoint 丢数据  | Backup API 读取源库一致性快照；测试覆盖 live WAL                             |
| 目标半写入                | 临时文件 + integrity_check + 指纹比较 + 原子 rename                          |
| 来源归属错误              | 保守判定；不明/损坏阻断，不建 empty 库                                       |
| registry 提交失败         | target 已验证但未 active；状态保留，重试恢复                                 |
| 磁盘失败/中断             | 源库、备份、目标隔离；状态 FAILED，可重试                                    |
| 旧 token 泄漏给新账号     | key 按账号命名；只在已验证绑定迁移；不明归属不迁移                           |
| WebView A 配置 + B 数据库 | 启动先读 native context，再动态加载 cloud；配置/token key 同 account id      |
| 降级旧版本                | 旧版本只看到根目录旧库，会看不到迁移后的新写入；发布说明必须声明，不自动回写 |

## 9. RC2-B 实现契约

RC2-B 必须建立在以下底座上：

- 账号切换前：停止同步、停止 reminder timer、取消当前账号系统提醒。
- 原子持久化 active account；关闭旧 `TodoStore`；旧 `Arc` 持有者必须在 close 后拒绝写入。
- 重新创建 `AppState` 和 WebView，重新加载 account context、cloud config、token。
- 每个账号独立 device_id/client_seq/outbox/shadow/cursor。
- 账号删除先写 pending marker，失败可重试，禁止半删除。
- 归属不明的人工确认入口需要在 RC2-B 或独立迁移工具中完成。
