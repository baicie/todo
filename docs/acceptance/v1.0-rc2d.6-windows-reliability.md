## 3. Windows Toast 根因

### 3.1 插件/平台事实

- `apps/native/src-tauri/Cargo.lock` 锁定 `tauri-plugin-notification 2.7.0`；
  Windows 后端使用 `notify-rust 4.18`。
- 插件 Windows 支持说明：仅安装后的应用正常；开发/未安装可显示 PowerShell
  名称/图标。
- Tauri 配置 identifier 即 AUMID：QA `app.shishi.todo.qa`。
- QA NSIS 安装创建了
  `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Shishi QA RC2D.lnk`。
- 插件文档明确：Windows 点击只在 Toast 仍在屏幕时报告，进入 Action Center 后
  不再报告。Rust handler 只在进程存活时存在。

### 3.2 端到端诊断

最终 installed QA run `rc2d-20261026T055128Z`：

1. QA task 创建成功。
2. `schedule_reminder` 返回 `scheduled`，fireAt `2026-10-26T05:52:07Z` 左右。
3. Windows registry `app.shishi.todo.qa\LastNotificationAddedTime` =
   `2026-10-26T05:52:09.2154823Z`。
4. `%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db` 中存在
   `app.shishi.todo.qa` 的 `toast` 行：
   - 标题：`QA Toast rc2d-20261026T055128Z ...`
   - body：`QA isolated Toast fixture rc2d-20261026T055128Z`
   - action content：`打开任务`
   - arguments：`shishi.task.v1:default:<task>`
   - expiry 约 7 小时。
5. UIA driver 在同一时间窗口内没有找到属于该 marker 的 on-screen `打开任务`
   Button，返回 `NOT_RUN`。

**根因结论**：调度、ActionType 注册、`show()` 和 Windows 平台接收均成功；
Toast 被平台记录。失败发生在**呈现/UIA 可见性**：当前会话没有暴露 on-screen
Toast banner 给 UIA（可能被 Focus Assist/通知横幅设置抑制，或已进入 Action
Center）。不是 Rust scheduling 失败，也不是 AUMID/安装缺失。

Action Center 历史可以存在，但插件 2.7.0 不报告离开屏幕后的点击；当前代码没有
Windows 原生冷启动激活入口。因此 `cold-start-activation` 是明确产品能力缺口。
