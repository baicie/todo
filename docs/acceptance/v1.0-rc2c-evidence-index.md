A checksum printed in a report is not independent proof that the exact binary was built from the merged commit. ## RC2-D evidence policy

New RC2-D runs use `scripts/qa/native/run-windows.ps1` and write to `artifacts/native-qa/<run-id>/`:

- `manifest.json` — run status, app/installer SHA-256, QA/production data-root presence.
- `environment.json` — OS/CPU/memory/Rust/Node/pnpm/WebView2/Tauri CLI.
- `provenance.json` — git commit/branch/status and build references.
- `tests.json`, `timeline.json`, `performance.json`, `logs/`, `screenshots/`, `summary.md`, optional `fault-evidence.jsonl`.

A RC2-D claim is only VERIFIABLE when the run manifest names a git commit and artifact SHA, and the evidence bundle is available for inspection. Local-only bundles that are not attached to a run/PR are `UNVERIFIABLE_LOCAL_EVIDENCE` until attached.

## Redaction rules

Evidence bundles must not contain:

- refresh tokens, access tokens, authorization codes or passwords;
- real user email/account data outside the QA namespace;
- production Credential Manager service contents;
- full production database paths or dumps.

QA accounts use `*.example.test`; credentials are written only to the QA credential service namespace and are removed by the run.
