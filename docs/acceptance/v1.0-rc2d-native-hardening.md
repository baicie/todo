## 5. 账号切换、RuntimeGate 与 SQLite

- journal phase/PREPARED/restart recovery 行为保持 RC2-B 不变量；新增只读 request 预校验，避免 stale request 先取消通知。
- QA 真实运行验证：无效 target 不改变 active account；prepared 注入失败后 active account 不变。
- RuntimeGate drain 2s、request guard、abort 仅 PREPARED 的既有测试继续通过。
- SQLite 事务边界未改变；`import_data` replace 模式跳过已删除行的存在性探测（100k 导入优化），仍保留单事务和 outbox 语义。
- 未运行：进程级切换 kill/restart 全矩阵（RC2-C 历史证据不升级）。

## 6. 凭据边界与 legacy 迁移

- 生产 `app.shishi.todo.secure-token` 保持不变；QA 使用 `app.shishi.todo.rc2d-qa.secure-token`。
- `CredentialBackend` 覆盖 get/set/delete；key 策略仍只允许 active account 的 refresh key。
- legacy 迁移顺序：若目标 key 已存在，**不覆盖**；仅清理 legacy。否则写目标 → 读回校验 → 删除 legacy；删除失败保留两份供幂等重试。
- 新增测试：已存在新 token 不被旧 token 覆盖；删除失败保留新 token；set/get/delete 失败不删除旧值。

## 7. 提醒与通知点击

- `reconcile_reminder_queue` 现在批量核验取消结果；取消成功但队列仍返回旧项记为 `failed`，不冒充 `cancelled`。
- legacy/foreign 队列清理、A/B 混合、同 ID 替换、重启清理 fixture 单测通过。
- 通知 action 使用 `NotificationTargetV1`（account/task/sourceVersion=1）；Native 校验 registry active、实际 store account、RuntimeGate lease、task 存在。
- `native_take_notification_activation` 在交付时再次校验；pending 队列有界；重复/过期 activation 不打开任务。
- 正文 tap 不携带 target，因此产品契约是“打开任务”按钮 action；**真实 Windows Toast 点击未执行，标记 NOT_RUN**，不伪造 PASS。

## 8. QA 隔离与证据

- QA identifier：`app.shishi.todo.qa`；QA 数据根：`%APPDATA%\app.shishi.todo.qa`；生产数据根在运行前后均不存在。
- `qa_build_identity` 在生产返回 `isQa:false`；QA harness 在**任何破坏性操作前**拒绝非 QA build。`run-windows.ps1` 另有 ProductName `Shishi QA RC2D` 校验。
- Fault config 仅通过 `--rc2d-fault-config` 读取；`deny_unknown_fields`、严格 identifier、evidence path 禁止生产数据根；生产无 arm IPC。
- Evidence 为 run-bound：复制 config 到本次 run 目录并将 evidencePath 指向 QA 数据根本次 run 的专用文件，启动前删除旧文件；Windows 上该位置可稳定写入（artifacts 目录曾出现全 NUL 证据文件，因此不作为 app 的直接写入目标）。
- 证据目录：`artifacts/native-qa/<run-id>/`；提交到仓库的脱敏摘要见 `docs/acceptance/rc2d-evidence/`，包含真实 smoke/fault 测试结果、fault evidence、性能 JSON 和截图。

| ------: | ---: | ----------: | ----------: | ----------: | ----------: |
|   1,000 |    3 |    `425 ms` |    `453 ms` |  `3,444 ms` |  `3,444 ms` |
