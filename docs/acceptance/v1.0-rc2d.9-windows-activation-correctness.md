## B. D8 P1 修复

### ACK 语义

旧实现把 `opened/rejected/expired/duplicate` 全部加入 completed target 集合，
导致：

- rejected/expired 后相同任务未来合法提醒被无限抑制；
- activationId 去重和 targetKey 去重混在一起；
- 没有 TTL。

D9 修复：

- 只有 `opened` 加入 target 去重；
- `rejected` / `expired` / `duplicate` 清除 in-flight，但不写 target 去重；
- activationId ACK 单独保存在 bounded `acked` 集合（容量 32）；
- target 去重 TTL **300 秒**、容量 **32**；
- ACK 强制 sessionId + activationId + 当前 in-flight 匹配；
- 旧 session 不得 ACK 新 delivery；
- Native 校验仍在 delivery 前执行，WebView ACK 不能绕过。

测试覆盖：

- rejected → 同 target 新合法 activation；
- expired → 同 target 新合法 activation；
- opened → 相同 target 抑制；
- TTL 过期后允许；
- duplicate ACK 幂等；
- stale session ACK 拒绝；
- listener reload / requeue；
- queue overflow；
- second reload expiry；
- identical target distinct reminders；
- no delivery before ready。

Native notification/activation tests：**23 PASS**；native lib serial：**66 PASS**。

### 前端真实业务结果

`openTask` 从 `void` 改为 `Promise<boolean> | boolean`；前端在以下情况不 ACK opened：

- 任务详情不存在；
- repository 抛错；
- 5 秒 ACK timeout；
- 页面 abort / account switch。

App 实现：

```text
repository.getTask(taskId)
  -> task 存在
  -> setSelectedTask(task)
  -> setSelectedId(taskId)
  -> selectedTask().id === taskId
  -> true
```

只有返回 `true` 才 ACK `opened`；否则 ACK `rejected` 并提示。
Frontend tests：**87 PASS**（新增 async failure/timeout 方向）。

## C. Queue / Session 一致性

- pending FIFO、上限 8；
- in-flight 在 ACK 前保留；
- listener reload 首次 requeue，第二次 `ACTIVATION_EXPIRED`；
- `requeue_used` 在 ACK 后重置；
- session 丢失不确认新 delivery；
- 账号切换仍由 Native validate_target 栅栏；
- completed target 有 TTL/容量；
- process kill/restart 后内存队列不持久化（未声明恢复）；
- 没有新增持久化 pending 队列。
