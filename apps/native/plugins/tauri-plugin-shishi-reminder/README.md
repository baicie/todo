# tauri-plugin-shishi-reminder

Local Tauri 2 plugin that owns system-level reminder scheduling on Android and
iOS. Desktop reminder behavior stays in the application's in-process timer
queue; this plugin is only initialized on mobile.

The app never exposes these commands directly to JavaScript. A narrow Rust
`ReminderAdapter` calls the plugin handle, keeping the WebView IPC surface to
the existing reminder commands.

- Android: `AlarmManager` (`setAndAllowWhileIdle` by default, optional exact
  scheduling only when the special permission is available) + a broadcast
  receiver + `NotificationManager`, SharedPreferences persistence, and a
  `BOOT_COMPLETED` rescheduler.
- iOS: `UNUserNotificationCenter` local notifications with a 64-pending cap and
  a 30-day scheduling window; authorization is requested at runtime.
- Secure tokens: AndroidKeyStore AES-256-GCM with encrypted SharedPreferences
  records, and iOS Security.framework Keychain generic-password items. The
  native commands are `secureTokenGet`, `secureTokenSet`, and
  `secureTokenRemove`; the app wraps them in the existing `secure_token_*`
  commands. Removing an absent token is idempotent.

Build artifacts under `gen/` are generated by Tauri and must not be committed.
